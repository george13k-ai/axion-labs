# Сайт студии

Статические страницы и небольшой Node.js-сервер, который их раздаёт и принимает заявки из формы. Внешних зависимостей нет, нужен Node.js 18.17 или новее.

## Запуск

```bash
cp .env.example .env    # заполнить SITE_URL, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
npm run build           # собрать страницы из src/ в public/
npm start               # http://localhost:3000
```

## Где что менять

- `src/content.mjs` — название студии, контакты, услуги, цены, этапы, FAQ, варианты в форме. После правок: `npm run build`.
- `src/build.mjs` — разметка страниц.
- `public/assets/site.css`, `public/assets/site.js` — стили, анимации, меню, логика формы.
- `server/server.js` — раздача страниц, `/api/lead`, `robots.txt`, `sitemap.xml`.

## Как работает форма

1. Браузер проверяет поля и отправляет JSON на `POST /api/lead`.
2. Сервер ещё раз проверяет данные, ловит спам (скрытое поле и слишком быстрая отправка), ограничивает частоту: 5 запросов за 10 минут с одного IP. IP хранится только в памяти и на диск не пишется.
3. Заявка уходит в Telegram-бот. Сообщение «Спасибо» показывается только после ответа сервера `200 {"ok": true}`.
4. Если бот не настроен или Telegram не ответил, форма показывает ошибку, и человек может отправить заявку ещё раз.

## Публикация

За nginx или другим прокси поставьте `TRUST_PROXY=1`, чтобы ограничение частоты видело настоящий IP. Держите сервер под process-менеджером (systemd, pm2) и включите HTTPS.

## GitHub Pages

На Pages нет сервера, поэтому там собирается статическая версия: `npm run build:pages` кладёт её в `dist/`. Форма в ней заменена блоком контактов, а ссылки начинаются с `PAGES_BASE`. Адрес и путь задаются в `src/content.mjs` (`PAGES_SITE_URL`, `PAGES_BASE`).

Публикация идёт сама: при каждом пуше в `main` workflow `.github/workflows/pages.yml` собирает `dist/` и выкладывает его.
